# Changelog

Every mainnet deploy of the program is listed here with its commit, the verified build hash and what changed. Breaking changes to account layouts, instructions or events are announced here at least one NFL week before they are deployed.

## Unreleased

- Toolchain (2026-10-28): Surfpool 1.6.1 → 1.7.0 in CI. The release carries Surfpool PR #876 (finalization depth gated on the Alpenglow feature), the condition the SDK finality entry below was waiting on: started with `--feature A1pengvuM6JEcyNuTnMqepBKhwHE3N6PmUrdATGawhJS`, `getSlot` at `finalized` equals `confirmed` (measured on the release binary: equal over consecutive reads; 30 slots behind without the flag, as on 1.6.1). Anchor 1.2's `[surfpool]` table has no feature pass-through, so the public localnet suite runs without the flag and confirms at `finalized` 30 slots (6 s) behind the tip, which the suite's timings allow; the private harness and the cloud localnet pass the flag.
- Rent at mainnet's rate (2026-10-28): Surfpool 1.7.0 also applies SIMD-0437-2 (5 080 lamports per byte, active on mainnet since epoch 1033), which 1.6.1 did not. The localnet suite's rent assertions follow mainnet: a `GameRecord` is 1,427,480 lamports and a pool's pool + vault + counter about 0.010 SOL (9,652,000 for SOL, 10,490,200 for SPL), where the documents said 0.014 SOL from the old rate. Nothing in the program assumed a figure (rent comes from the `Rent` sysvar), and clients read the creation fee from the chain.
- SDK finality (2026-10-23): the chain layer reads, simulates, subscribes and confirms at `finalized` everywhere it read `confirmed` before, through one exported constant, `COMMITMENT`, and the `Commitment` type. Under Alpenglow (mainnet-beta since 2026-10-21) `finalized` is the confirmed slot and `confirmed` is removed in a later Agave release. `prepareTransaction`'s `blockhashCommitment` defaults to it; `signAndSend` confirms at it, and when the finalized block height passes `lastValidBlockHeight` it reads the ledger's history once before declaring `BlockhashExpired`, so a transaction the status cache missed is found rather than reported as never processed. The program is unchanged. On a local validator without the Alpenglow feature `finalized` trails the tip by 31 slots (Surfpool 1.6.1; the gate that makes it one slot when `A1pengvuM6JEcyNuTnMqepBKhwHE3N6PmUrdATGawhJS` is active is in review upstream), which the SDK does not work around.
- Dependency audit (2026-10-24): RustSec published RUSTSEC-2026-0387 (`crypto-bigint` 0.5.5, timing variability in operations meant to be constant-time; patched in 0.7.6). The crate is dev-side only here — `solana-syscalls` → `solana-secp256k1-recover` → `k256` 0.13 under Mollusk and the bencher; it is in no built program's tree — and `k256` 0.13 pins the 0.5 line, so there is no patched version to move to until Agave takes `k256` 0.14. Ignored in `.cargo/audit.toml` with the path recorded, the fifth entry and the first that is not an `unmaintained` notice. The program is unchanged.
- Program id (2026-10-23): `declare_id!`, `Anchor.toml`, `idl/mybarpool.json` and the generated client now carry the mainnet id, `5SrgR4uZH2xqvNvJVgLddFuLMLaiYbbsXtmtS4rvLfD6` (config PDA `8rDtdMvr7ZwxyrX1wSMjHYTbmcmS3rLVF3HzBbUEKXfK`), in place of Step 0's placeholder `3jk4YM9xnpoMYK3nuaUHZ59SCDxwExfT9EHxwP2wRMBw`. The id is the only byte that changes in the program; nothing is deployed on any cluster yet, and the deployment is announced here when it lands. The test fixtures captured from localnet keep the address they were captured under and bind the id from the fixture, so they are unchanged.
- Generated client (2026-10-23): `@codama/renderers-js` 2.5.0 → 2.6.0 and `@solana/kit` 8.4.0 → 8.5.0 (the peer range is now `^8.5.0`, which the app and services already satisfy). The generated account fetchers, PDA finders and `*Args` types accept an `Address` or any object with an `address` (`HasAddress`), which Kit 8.5's address encoder handles; nothing the SDK exports by hand changes shape, and the §10 schema snapshot is unchanged. 2.7.0 and 2.8.0 were tried and not taken: the program-address override they render passes `programAddress: a ?? b` into an optional property, which `exactOptionalPropertyTypes` (on in this package) rejects, so the generated client would not compile; revisit when upstream fixes it. The program is unchanged.
- SDK confirmation (2026-10-23): `signAndSend`'s polling path, once the block height passes `lastValidBlockHeight`, reads the ledger's history once (`getSignatureStatuses` with `searchTransactionHistory`) before declaring `BlockhashExpired`. The status cache holds recent slots only and, behind a load-balanced RPC, one node's; a transaction that landed but was missing from it read as never processed, and the caller's one allowed retry would have sent it a second time. The program is unchanged.
- Yahoo as a fifth score source (2026-10-23): `ScoreSource` gains `yahoo` and `SCORE_SOURCES` lists five; `SourceGameIds.yahoo` carries Yahoo's game id (`nfl.g.<yyyymmdd><nnn>`) and `buildGameIdMap` indexes it; `SOURCE_TEAM_TABLES.yahoo` maps Yahoo's 32 team ids (`nfl.t.1` … `nfl.t.34`, with no 31 or 32) to the shared team ids. No program change. The reason is in the architecture document's decisions log: a final now has three fast voices under the unchanged three-voice agreement rule.
- Internal security audit (2026-10-23): four independent reviews of the program against PROGRAM.md, before any deployment, reported in [`docs/audits/2026-10-23-internal-audit.md`](docs/audits/2026-10-23-internal-audit.md). Program changes, all pre-mainnet so no account on any cluster is affected: `sample_var` and `draw` now require the `Var`'s end slot to be the one `set_var` recorded on the pool (`VarEndAtMismatch` 6066), closing a re-roll the keeper had as the `Var`'s authority by closing and re-opening it; `set_var` refuses an end slot more than `VAR_END_AT_MAX_LEAD` (1,500) slots ahead; `replace_var` takes the `SlotHashes` sysvar and is refused until the recorded end slot is gone from it (`SampleWindowOpen` 6067); `draw` takes the game record and is refused once a quarter is posted (`DrawAfterScores` 6068); `update_kickoff` is bounded 72 hours each side of the scheduled kickoff; the seven paying instructions (`settle`, `close_pool`, `return_boxes`, `return_sponsorship`, `split`, `reclaim`, `reclaim_sponsorship`) take the SPL Memo program on SPL pools and write a Memo before a transfer to a Token-2022 account that requires one, so a winner's account setting cannot block a settlement; `split` continues a pool that `reclaim` moved into `Split` whatever the game's status; `close_pool` reports SOL dust with a saturating subtraction; a `Link` pool's gate key may not be the program id; `solana-security-txt` is embedded in the binary. Sixty-nine errors. The schema snapshot was re-frozen for the three instruction account-list changes (`draw`, `replace_var`, the memo program), the last time that happens before mainnet.
- Box sponsorship (2026-10-21): the one addition to the program since the Step 8b fixes, made before any deployment so no account on any cluster is affected. `sponsor_box(box_index, amount)` is `sponsor` plus the sponsor's mark on one box (0–24, one sponsor per box, `BoxAlreadySponsored` 6065 otherwise); the money is a sponsorship like any other and the box keeps its owner and its prizes. `Pool` gains `sponsored_boxes` (u32) out of `reserved` (96 → 92; same size, no earlier offset moves) and `Sponsorship` gains `boxes` (u32; 81 → 85 bytes — the recorded exception to PROGRAM §3's rule for the small accounts, see §3.7); the event `BoxSponsored` and the error are appended. 27 instructions, 6 account types, 25 events, 66 errors; the schema snapshot is regenerated and the compute-unit table gains `sponsor_box_new`. SDK: `sponsorBoxInstruction`, `SPONSORSHIP_SIZE` 85, `SPONSORSHIP_OFFSETS.boxes`, `BoxSponsored` decoded.
